# Governance

Subjective C begins as a maintainer-led project. Maintainers merge changes, publish releases, steward the manifest contract, and moderate the community.

Large architectural decisions should be proposed as numbered RFCs. An RFC remains open long enough for meaningful review and should record alternatives, invariants, compatibility, migration, and unresolved risks.

As the contributor base grows, maintainership should be earned through sustained technical contributions, thoughtful review, reliable project stewardship, and alignment with the safety and accessibility principles of the project.
